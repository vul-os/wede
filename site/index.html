What's inside

Everything in one process.

Not a shell around VS Code, and not a hosted service with a self-host tier bolted on. wede is one Go binary that opens your folders, talks to your git, spawns your shells, and lets other people in.

Real-time, actually

Multiplayer cursors, live presence, and conflict-free concurrent edits — CRDT-backed by pure-Go reearth/ygo, wire-compatible with Yjs. See who is in the workspace and which file they're staring at.

CRDTpresence rosterautosave to disk

Terminals you share

Real PTYs streamed over WebSocket to everyone in the workspace at once — same session, same output, same keystrokes. Dock them, float them, rename them. Run shells, SSH, docker, whatever the host can run.

creack/ptyxterm.jsmulti-subscriber

Git without leaving

Visual commit graph, blame, side-by-side diffs, per-hunk staging, conflict resolution, cherry-pick, revert, reset, merge, stash, tags, remotes. It drives your real git binary — no reimplementation, no surprises.

commit graphhunk stagingconflict UI

Workspaces & share links

Open many projects on one host — multi-root, switchable. Invite people with links scoped to editor or viewer. Tokens are SHA-256-hashed at rest, compared in constant time, rate-limited on redeem, and revocable at any moment.

editor / vieweroptional TTLrevocable

LSP & DAP, extensible

gopls, typescript-language-server, pylsp and rust-analyzer are wired out of the box; so are dlv and debugpy for debugging. Add any other server or adapter through ~/.wede/lsp.json — no recompile, no marketplace.

completionhover · go-to-defbreakpoints

Chat that lives in the repo

The public channel is .wede/chat.md — committed alongside your code, greppable, readable by your tooling. Git activity posts itself into the thread. A private channel stays auto-gitignored.

per workspacegit activity feedmarkdown on disk

API client, built in

Postman-shaped requests sent server-side, so CORS never gets a vote. {{variables}}, environments, saved collections in .wede/requests/. Loopback, private-range and cloud-metadata addresses are blocked after DNS resolution — an SSRF guard most API tools skip.

no CORSSSRF-guardedcommittable

Search that keeps up

ripgrep when rg is on PATH, a pure-Go walker when it isn't — same UI either way. Regex, whole-word, include/exclude globs, context lines, and project-wide search-and-replace with a preview before anything is written.

regexglobsreplace w/ preview

One file to deploy

Go embeds the entire React frontend. Copy one binary to a VPS, a NAS, or a Raspberry Pi and run it. Five release targets, five direct Go dependencies, and 230 Go tests behind it.

Collaboration

Send a link.
That's the whole flow.

No org, no seats, no invitations pending an email. You own the host; you mint a link; you revoke it when you're done.

  1. 1
    Open a folder as a workspacePoint wede at a directory. Open as many as you like — they live side by side on one host.
  2. 2
    Mint a share linkChoose editor (writes, git, terminals) or viewer (read-only, can still post in chat). Set a TTL if you want one.
  3. 3
    Work in the same roomCursors, selections, terminals and chat, all live. Files land on your disk, debounced and written atomically.
  4. 4
    RevokeOne click. The token's hash is dropped and the session dies with it.

Get started

Clone, build, open.

You need Go 1.25+ and Node 18+ to build it, and nothing at all to run it. The binary that comes out is the whole product.

bash
$ git clone https://github.com/vul-os/wede.git
$ cd wede && npm install
$ npm run build:all # vite → go:embed → ./wede
building frontend… ✓
embedding assets… ✓
./wede 19 MB
 
$ ./wede /path/to/your/project
wede listening on http://127.0.0.1:9090
workspace: project · owner login required
go 1.25+node 18+ loopback by default

Set a password first

Copy wede.config.example.json to wede.config.json and replace the CHANGE_ME_BEFORE_USE placeholder. Three bad attempts locks the login, and the lockout survives a restart.

There's an installer, with caveats

install.sh fetches a release binary and generates a config with a random password. It does no checksum verification, so download and read it before you run it rather than piping it into a shell.

Reaching it from elsewhere

wede binds to 127.0.0.1 and speaks plain HTTP on purpose. Put Caddy or nginx in front for TLS, or use the built-in tunnel — both paths are written up in Public access.

Know what an editor link is

An editor link hands over a real login shell as the user running wede. Treat those links like SSH keys, and read Hardening before you expose anything.

Security posture

Honest about the sharp edges.

Self-hosting moves the trust boundary onto you. Here is exactly where it sits.

Secrets are hashed at rest

Session and share tokens are 32 random bytes; only their SHA-256 hashes touch disk, in 0600 files. Comparisons are constant-time.

Roles are enforced server-side

Viewers cannot write, spawn terminals, or mutate git — the middleware gates the routes, not the UI. Redeeming a link is rate-limited to 10 tries per IP per minute.

Workspaces are untrusted by default

A cloned repo's .wede/tasks.json and formatter config do nothing until you explicitly trust that workspace. Paths are checked against symlink escape.

Editor links are shell access

An editor gets an unsandboxed login shell as the OS user running wede — full environment, full filesystem, your SSH keys. There is no sandbox. Share accordingly.
